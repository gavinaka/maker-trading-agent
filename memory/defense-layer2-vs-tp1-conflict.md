# Maker 浮盈防守层与止盈档金标口径

## 宪法级硬规则

1. **第一层防守只允许使用成交后后续形成并确认的 4H 级别 K 线极点**：
   - 空单：成交后、价格后续运行中确认的 4H 级别结构性极点高点。
   - 多单：成交后、价格后续运行中确认的 4H 级别结构性极点低点。
   - 报告阶段只能预先写第一层触发价，不能预填移动止损的具体极点价格。
   - 禁止把历史 4H 高/低点、当前未完成 K 线高/低点、1D high/low 或任何报告生成时已存在的价位写成第一层移动止损价。
   - 禁止改写为 1H、1小时、15m、15分钟或笼统“小时级别”极点。

2. **每一层防守必须写出明确触发价格**：
   - 第一层：浮盈首次达到 +1.5R 后触发。
   - 第二层：进一步达到约 +2R / TP1 附近后触发。

3. **防守层只移动止损，不做仓位扣减**：
   - 第一层：触发后，移动至成交后后续形成并确认的 4H 级别极点止损，并取消所有加仓。
   - 第二层：只设保本损。
   - 禁止在第一层或第二层写“减仓/平仓 X%”。

4. **仓位扣减只发生在止盈档**：
   - TP1：减仓 50%。
   - TP2：清剩余仓位。
   - 计划仓位账必须 100% 闭合，防守层不得与 TP 档重复扣减。

## 事故样本

- 2026-06-27 后多份报告把第一层从 4H 极点漂移为 1H。
- 2026-06-29 与 2026-07-02 多份报告进一步漂移为 15m / 15分钟极点。
- 2026-07-06 午报暴露新的规则缺口：虽写了“4H极点”，但提前把历史/当前图面价位写成未来第一层移动止损价。正确逻辑是 Maker 成交后，根据后续价格行为形成并确认的 4H K 线结构性极点动态确定止损价。

## 验收

`outputs/report_lint.py` 必须在发布前硬拦：

- 第一层缺 4H / 4小时；
- 第一层出现 1H、1小时、15m、15分钟、笼统小时级别；
- 第一层缺触发价或缺“极点”；
- 第一层在触发价之后继续出现具体价位，疑似预填未来 4H 极点止损价；
- 第一层未声明极点来自成交/入场后后续形成并确认；
- 第二层缺触发价、缺保本损，或防守层出现仓位扣减。
