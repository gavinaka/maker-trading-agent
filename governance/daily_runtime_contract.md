# 日报运行合同（紧凑入口）

此文件只承载不随报告变化的机械入口；完整业务规则按 `context_pack` 的 phase read plan 分阶段读取，禁止每轮重复通读全部仓库。

1. 先运行 `runtime/automation_memory_guard.py`，再运行 `runtime/daily_report_status.py`。
2. `complete` 正常结束；其它状态严格按 status 输出的 `next_action` 处理，不抢占别的 lease。
3. 分析锁前只允许 `runtime/prelock_read_policy.py` 声明的路径；搜索只能使用 `runtime/prelock_safe_search.py`。每个阶段先运行 `runtime/phase_contract.py` 生成一个 hash-bound bundle，只读该 bundle 一次，禁止对同一权威文件反复分段读取。技能入口只读一次，`workflow_entry` 不重复装载技能；分析阶段必须完整读取 `analysis_orderflow`、`analysis_chart_winrate`、`analysis_agents` 三包。任何 bundle 超过 76KiB 或 `complete` 非 true 都硬停，禁止截断或删减权威。`analysis_agents` 是兼容保留的阶段名，只装载当前 `reasoning_depth + scoring_contract` 综合契约；`agents/` 与 `state/` 属参考设计层，不得进入生产 authority manifest 或 phase bundle。
4. `begin-session → immutable capture` 后用 `runtime/host_capability.py` 绑定宿主。仅 legacy 进入 `prepare`：请求 exact `gpt-5.6-sol/high`，实际须 `>=high`。vNext 不走 `prepare`，由 `runtime_vnext/effort_policy.py` 请求 exact `gpt-5.6-sol/xhigh`，实际须 `>=xhigh`。Prompt／布尔自称无效。
5. 先用 `runtime/reasoning_contract.py` 生成 v2 强类型合同：当前证据、同锚三问、足迹交叉验证、多周期转换、增量 VRVP/猎杀/清算图/ETF 维度、账户分流、三情景树、支持/反证、评分、计划时置信度和 Word/Notion 语义投影缺一不可。再用 `runtime/adversarial_review.py` 对每个承重 claim 的真实 support/counter 节点做隔离第二遍反证。评分、置信度和 Maker 风险数学最后由绑定同一 reasoning contract 的 `runtime/decision_contract.py` 生成。
6. `certify-reasoning` 将工作稿、capture、transition、host capability、golden、reasoning、adversarial review 与 decision contracts 一起绑定；reasoning contract 必须机械复算 C01–C81、效果背离与 OI/价格语义，禁止资金费率翻向，并保证盘面30为 TradingView-only 的方向中立机会质量分。TradingView profile 当前固定为 `user_drawn_manual_only`：平台内置VRVP必须隐藏且永不取值；可读手绘区域只主判位置/概率，手绘区域不足则 `zones=[]`、原因必填、流动性猎杀分0且不输出POC/VAH/VAL/HVN/LVN数值或概率落点。Coinglass清算热力图是独立辅助 observation，不得替代不足的手绘profile、加盘面分、改盘口分或翻方向；1D/4H/1H/15m 四周期必须分别保留，15m 只用于 Maker 入场精度，profile不足不阻断四周期结构。随后必须 `lock-reasoning` 冻结独立分析。vNext `decision-model-v4` 必须绑定 v2 run id/hash/mode，并分别绑定主账户计划与 Maker 完整候选计划：区间化 2–5 档、策略类型、Maker、OKX、标的、计划持仓金额、固定 5x、左/右侧、标准化 cannot-do 与当日有效期。shadow 只写 no-live-state continuity，禁止读取实仓、旧单或 pretrade；production 才可在锁后读取 hash-bound continuity 与同日个人执行资格。个人执行资格只能改变 `execution_action`，不得改变计划、方向、评分、胜率、价格或风险；任一字段缺失或冲突都由既有 decision/report 门拒绝，不另增独立硬门。
7. `combined → report semantic projection → cards → certify-draft → preflight-report → lock-analysis → finalize-post-lock → commit → canonical render → Word QA → publish → frozen verifier → unique page → record-delivery-evidence → deliver` 缺一不可。draft/preflight 必须证明金标准承重语义同时存活于可见正文和③后附，Notion 由同一 combined 确定性派生且不可压缩丢失。`record-delivery-evidence` 只从真实 render/QA/publish manifest 原子生成 context 机械证据块，`deliver` 仍独立回读验证。
8. 晚报不生成独立审查。外置交易准确性评估由 Technical expert 在交付后一小时执行，不属于生产链。
9. 报告深度以六源证据、因果链、反证、失效路径和机械计算完整性判断，不以字符数、价位引用次数或工具调用次数判断。
10. 交付后运行 `runtime/host_usage_import.py` 导入当前 `CODEX_THREAD_ID` 的真实 token/轮次/工具指标；目标为模型轮次不超过 80、非缓存输入不超过 80 万。超标只形成效率告警，不回写或改变交易结论。
