# Trading-System Daily Report

1. Read `sessions/日报SOP.md` completely through the bounded `workflow_entry` transport defined in step 3; it is the committed executable authority for Codex runs. Never start with a direct raw read of the SOP.
2. If `.claude/skills/daily-report/SKILL.md` exists on this machine, treat it only as a local Claude Code compatibility mirror. It may be consulted for drift detection, but it is not allowed to override `sessions/日报SOP.md` or any committed authority file because `.claude/` is git-ignored.
3. Run `runtime/context_pack.py --date <date> --slot <slot>` once and inspect its `authority_sha256`, `authority_manifest`, `authority_read_plan`, and `read_policy.prelock_safe_read_policy`. Always read the mandatory guardrails in `read_policy.mandatory_guardrails_always_read`; expand the remaining authority files by the current phase/source need instead of loading the full authority set blindly. The skill itself is loaded exactly once by the skill entrypoint and remains hash-tracked in the authority manifest; `workflow_entry` therefore contains the full SOP only and must not reload this skill. Read `workflow_entry` and every later phase through the bounded transport protocol: run `runtime/phase_contract.py ... --phase <phase> --emit-part 1`, inspect `part_count` and `bundle_sha256`, then read every remaining part index exactly once. Every part must have the expected BEGIN/END marker, the same bundle hash and part count, continuous one-based indexes, and `part_bytes<=28672`; a missing, duplicate, out-of-order, oversized, hash-mismatched, or truncated part is a hard stop. Do not directly reread the persisted bundle or its source files. Analysis authority remains split into `analysis_orderflow`, `analysis_chart_winrate`, and `analysis_agents`; all three are mandatory and together equal the former full analysis set. The logical phase bundle must report `complete=true` and remain within its logical byte limit; transport splitting never permits omitting or shortening a method file. If the authority digest changed unexpectedly or the phase need is ambiguous, hard-stop for maintenance instead of improvising an untracked read. Before the analysis lock, never directly read the full context ledger, aggregate memory, prior reports, old outputs, old runtime state, reviews, quarantine files, or prior analysis/decision archives. Do not run naked repository-wide search for pre-lock facts; use explicit paths from the context pack/read plan or the safe rg excludes from `runtime/prelock_read_policy.py`.
4. Preserve the Claude Code-era guardrails from committed authority, not from the ignored `.claude` mirror. These are mandatory: `memory/independent-report-no-user-reference.md`, `memory/precise-numbers-no-fuzzy.md`, `memory/report-chinese-only-narrative.md`, `memory/notion-publish-checklist.md`, and `memory/stability-contract.md`.
5. Keep this workflow isolated. Do not invoke or mix any sibling or cross-workflow process.
   Daily eligibility has exactly one pre-report and pre-trade gate: the same-day Notion `开仓前状态门禁` row and its final `主观结论`. `心智自控日记表` and `心力监控模块` are end-of-day review inputs only; never query, require, infer from, or use them to modify report/trading eligibility. A missing, wrong-date, or internally contradictory gate row is a hard stop for manual confirmation, not permission to substitute review data.
6. Optimize only deterministic collection and mechanical execution.
7. Before the analysis lock, do not read or use Notion actual-position facts for Maker/main decisions. Positions may be reconciled only after the independent report hash is locked, and may not change score, win rate, direction, entry, stops, targets, or whether Maker places an order.
8. Before collection, run `session_runner.py begin-session --date <date> --slot <slot>` and retain its lease token. Pass that token to capture and every subsequent runner command. A second slot/date may not begin until delivery closes the lease; interruption requires explicit `abandon-session` or `recover-session` with a reason. If an immutable same-date/same-slot capture manifest already completed successfully before an audited hard stop closed the original lease, do not edit the manifest and do not hand-copy evidence. Resume only by running `session_runner.py recover-session --date <date> --slot <slot> --from-lease-id <capturing_lease_id> --reason <explicit reason>` and then `prepare` with the new lease token and the exact old manifest path; the runner must record `recovered_from_workflow_lease` and `capture_lease_recovery`. If the archived lease cannot be validated, rerun capture instead of bypassing the lease gate.
   Report Gate/Lease creation is mutually exclusive with `runtime/authority_mutex.py` maintenance windows. If an authorized maintainer holds that mutex, hard-stop before production; never delete or bypass the maintenance lock. Maintainers must claim the mutex before changing authority/runtime files and release it in a `finally`-equivalent cleanup after validation. If a maintainer hard-stops and loses the token, recovery is two-stage: after rechecking no active Gate/Lease and obtaining explicit authorization, run `authority_mutex.py request-recovery --reason <explicit orphan evidence>`; preserve its challenge and exact lock SHA, wait the enforced five-minute cooldown, recheck that the lock is still orphaned and unchanged, then run `authority_mutex.py recover --challenge <challenge> --expected-lock-sha256 <sha> --confirm-orphaned`. Direct deletion and immediate recovery remain forbidden.
9. Capture into the immutable manifest path printed by `capture_all.js`/`capture_delta.js`. A full baseline run must use `capture_all.js`, which runs `cleanup.js` first; do not bypass it with manual sub-captures. For midday/evening, `capture_delta.js` is still required to refresh all six sources; delta means conservative sequencing, source fingerprint comparison, and one bounded full fallback, not permission to skip FedWatch or reuse morning/prior evidence. Capture cleanup only removes expired dynamic inbox screenshots and BlockBeats cards older than `CLEANUP_KEEP_DAYS` days, never current-day evidence or immutable snapshots. Post-delivery retention cleanup is automatic: successful `session_runner.py deliver` executes `runtime/report_retention.py`, writes `runtime_state/<date>/retention_cleanup_<slot>.json`, keeps canonical local Word drafts, Notion pages, delivery/lease/automation minimal state, and removes older reproducible local non-Word artifacts according to `REPORT_RETENTION_KEEP_DAYS` days. Use `--skip-retention-cleanup` only for explicit troubleshooting. BlockBeats must be collected with the page's `重要快讯` filter selected and must cover all available important flashes from the 12 hours before the capture time; require `blockbeats.json` to contain `"important_only": true`, `"capture_window_hours": 12`, `"window_covered": true`, at least three `candidate_rows`, exactly three `selected_rows`, and `rows` equal to the selected top3 by fundamental-impact priority. Farside BTC ETF Flow is a required source: require `farside_btc_etf.png` and `farside_btc_etf.json`, with title `Bitcoin ETF Flow (US$m)`, a parsed Total column, and numeric latest daily `total_usd_m`. Hard-stop instead of falling back to unfiltered news, a shorter BlockBeats window, stale ETF-flow data, or inferred ETF-flow numbers. After collection and before source validation, confirm the highest available model and MAX effort, then run `session_runner.py prepare` with `--capture-manifest <exact path> --lease-token <token> --max-reasoning-confirmed`; halt if this cannot be confirmed.
   `prepare` also activates `runtime/prelock_guard.py`: prior-session judgment artifacts (`sessions/context_log.md`, prior `analysis_*.json`/`decision_*.json`, prior combined/payload/render outputs) are quarantined until `lock-analysis` succeeds, and the guard manifest embeds the safe pre-lock read policy. The repository `.rgignore` hides known prior-judgment surfaces from default `rg`, but this is a guardrail, not permission to search broadly. Do not bypass this guard, manually restore/read quarantine files, or search `sessions/archive/**`, old `outputs/**`, old `runtime_state/**`, `reviews/**`, or `memory/MEMORY.md` before the report hash is locked. `lock-analysis` restores guarded files for post-lock continuity review; `abandon-session`/`recover-session` restore them on interruption.
10. Use MAX reasoning for source validation, visual transcription, analysis, scoring, win rate, risk, scenarios, decisions, writing, and review.
11. Recompute the complete analysis from the report slot's freshly collected full valid six-source evidence for every morning, midday, and evening report. Never reuse prior evidence snapshots, features, scores, win rate, risk, or judgment. The six required sources are BlockBeats, Coinglass, Exocharts, FedWatch, Farside BTC ETF Flow, and TradingView. Farside must be used as the spot-side liquidity confirmation signal: price down + ETF outflow confirms/strengthens bearish health, price up + ETF inflow confirms/strengthens bullish health, and disagreement weakens the move. A logic/methodology hash change invalidates analysis only and never authorizes redundant evidence capture.
    Golden reasoning alignment is the learned compact contract in `scoring/golden_report_reasoning_alignment.md`, not a runtime comparison against historical Word files. After `prepare`, the runner writes `runtime_state/<date>/golden_reasoning_<slot>.json`; do not reopen pre-2026-06-26 local Word/combined reports, and do not pad the MD after output to mimic length, price-reference count, or rubric count. Reasoning style, depth, and dimensions are hard aligned; old Word/Notion formatting only needs near-100% alignment while field semantics, trading numbers, Word QA, and publish verifiers remain hard gates.
12. Before writing the formal `outputs/<date>_<slot>_combined.md`, create the internal pre-output work file `runtime_state/<date>/reasoning_work_<slot>.md` from the completed MAX analysis. It must cover six-source accuracy, pivot/CVD/SMA20/VRVP calibration, score synthesis, win-rate rubric, refutation/invalidation, and risk math. Then run `session_runner.py certify-reasoning --date <date> --slot <slot> --work-file runtime_state/<date>/reasoning_work_<slot>.md --capture-manifest <exact path> --lease-token <token> --confirm-six-source-accuracy --confirm-critical-data-calibrated --confirm-score-winrate-risk-refutation --confirm-no-formal-md-written --confirm-no-posthoc-reasoning --confirm-max-reasoning`. From 2026-07-11 evening onward, next run `session_runner.py prepare-report-contract --date <date> --slot <slot> --gate-summary <standalone gate value> --decision-contract runtime_state/<date>/decision_contract_<slot>.json --lease-token <token>` and copy its three generated canonical lines (gate, score/win-rate, risk math) into the formal report exactly once as standalone lines. Gate metadata or hand-recalculated variants are forbidden. From 2026-07-06 midday onward, `combined.md` is forbidden before the reasoning readiness manifest. Posthoc rationale or rubric backfill is a hard violation.
13. Maker floating-defense first layer must use the 4H candle extreme that forms and is confirmed after the Maker order is filled: use the post-entry confirmed 4H high extreme for shorts and the post-entry confirmed 4H low extreme for longs. The report may precompute the first-layer trigger price, but must not prefill the future extreme stop price from historical/current 4H highs/lows, 1D highs/lows, or any already-known price. Never use 1H/15m/hourly wording for the first layer.
14. After the formal `combined.md` is written from the certified reasoning work file, create the parameterized `outputs/<date>_<slot>_cards.json` and run `py outputs/generate_cards.py <spec>`. From 2026-07-11 evening onward, before preflight run `py runtime/session_runner.py certify-draft --date <date> --slot <slot> --report outputs/<date>_<slot>_combined.md --cards outputs/<date>_<slot>_cards.json --lease-token <token>`; this manifest hash-binds the report, cards, exactly three generated images, immutable capture, reasoning readiness, golden reasoning and canonical report contract. Only this certified set may be preserved across a same-slot recovery. Then run `py runtime/session_runner.py preflight-report --date <date> --slot <slot> --report outputs/<date>_<slot>_combined.md --lease-token <token>`. This pre-lock command revalidates all certifications, mechanically proves lint, exact canonical state extraction, daily payload derivation and source binding against one report hash, and binds both new manifest hashes. It must never rewrite, shorten or reinterpret analysis. Only after the preflight manifest passes may `session_runner.py lock-analysis ... --lease-token <token>` create the independent-analysis lock; lock-analysis replays and hash-compares the same deterministic contract. Do not read prior-session directions, scores, win rate, Maker decisions, or Notion actual-position facts until this report-hash-bound lock exists.
15. Review prior-plan continuity after the lock, then run `session_runner.py finalize-post-lock ... --lease-token <token>` with the applicable confirmations. Do not generate or publish a separate evening independent-review page. Trading accuracy evaluation is owned by the external `Technical expert` workflow and runs asynchronously after delivery; it is never a daily-report completion gate.
16. Commit only through `session_runner.py commit ... --lease-token <token>`; it must validate the analysis lock, pre-MD reasoning readiness, post-lock completion, report completeness, source coverage, and state allowlist.
17. Render only with `render_from_combined.py <combined> --date <date> --slot <slot>`. It produces exactly `outputs/<date>_<slot>_render.docx`, reuses a matching hash-bound result, blocks lone `>`/bad titles, and hard-stops before a third attempt. From 2026-07-11 onward the analysis lock must additionally bind the successful preflight manifest, preventing a payload-format discovery from forcing a post-lock reissue or second reasoning pass. From 2026-07-06 midday onward render also requires a hash-bound analysis lock that contains pre-MD reasoning readiness. From 2026-07-05 onward, `outputs/report_structure_gate.py` is a hard gate before render, before publish, and after DOCX render: human-facing titles must use `YYYY.M.D`, the combined draft must keep `## ① 正文` -> `## 不能做` -> `## ② Maker 计划` -> `## ③ 后附`, raw `---` is forbidden, legacy `五源` wording is forbidden, and the appendix must cover all six sources including Farside BTC ETF Flow.
18. Run `word_qa.py export`, inspect every generated page at MAX, then run `word_qa.py approve --confirm-visual-pass --reviewer <host>`. Do not create V2/V3/report/Chinese-named DOCX copies or temporary VBS/PS1 render scripts.
19. Build the final daily Notion payload only with `py outputs/daily_payload_builder.py outputs/<date>_<slot>_combined.md`; this must reproduce the preflight payload hash for the locked report. The combined Markdown is the only daily text source of truth, and hand-written `children` JSON or date-specific `_prepare_*` / `_notion_push_*` scripts are forbidden for new daily reports. Then publish through `publish_report.py`, which must verify `payload_source.kind=combined_md_to_notion_payload` and, from 2026-07-06 midday onward, the hash-bound analysis lock with pre-MD reasoning readiness before any Notion write. Parameterized daily payloads must be normalized to the `daily-gold-run-colors-v1` Notion run-level color template before any Notion write: labels stay default, fundamental parenthetical reasoning stays yellow, only the standalone price-realization phrase is green, technical daily/hourly paragraphs color their key signal clause such as regained/lost SMA or trendline pressure, trend confirmation colors the whole trend conclusion by its primary direction, support/pressure/TP/SL/notes use green/red/purple, and whole-block coarse coloring is forbidden. Only after render、Word-QA、publish、冻结 verifier 与唯一页证据都真实存在，运行 `session_runner.py record-delivery-evidence --date <date> --slot <slot> --page-id <id> --lease-token <token>` 原子写入并回读验证 `context_log.md` 的机械证据块；禁止手写 page/hash/manifest/PASS 标签。随后运行 `session_runner.py deliver --date <date> --slot <slot> --page-id <id> --lease-token <token>` 独立复验并交付。Boolean self-attestation is not delivery evidence.
    Normal publication always keeps the 240-minute executable-source freshness hard gate. The only exception is an explicit user instruction to finish an already analysis-locked historical time-slice without recapture. In that case, and only after the report hash, analysis lock, capture-manifest hash, and immutable evidence snapshot all validate, use `publish_report.py --allow-locked-timepoint-publish --locked-timepoint-reason <explicit reason> <payload>`. This records the failed current-freshness result and authorization reason in the publish manifest; it does not relabel stale evidence as fresh. Never use the flag to rescue an unlocked draft, a missing source, a mutable inbox file, or an implicitly delayed run.
    Legacy review builders and verifiers remain compatibility-only for historical pages. The active daily-report workflow must not call them or create a new `🔍` child page.
20. Treat user phrases such as `收工`, `如无问题即收工`, `完成后收工`, or any final-completion response as a hard completion trigger. Do not say the report is complete until the scoped completion gate is closed:

Successful `session_runner.py deliver` automatically executes retention cleanup for artifacts older than the retention window; keep canonical local Word drafts, Notion pages, and minimal delivery/lease/automation state.

A later slot must never overwrite, refresh, reinterpret, or satisfy freshness for an earlier slot.
