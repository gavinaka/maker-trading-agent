# Trading-System Daily Report

1. Read `sessions/日报SOP.md` completely; it is the committed executable authority for Codex runs.
2. If `.claude/skills/daily-report/SKILL.md` exists on this machine, treat it only as a local Claude Code compatibility mirror. It may be consulted for drift detection, but it is not allowed to override `sessions/日报SOP.md` or any committed authority file because `.claude/` is git-ignored.
3. Run `runtime/context_pack.py --date <date> --slot <slot>` once and inspect its `authority_sha256`, `authority_manifest`, and `authority_read_plan`. Always read the mandatory guardrails in `read_policy.mandatory_guardrails_always_read`; expand the remaining authority files by the current phase/source need instead of loading the full 50-file authority set blindly. If the authority digest changed unexpectedly or the phase need is ambiguous, read the affected authority files before proceeding. Before the analysis lock, never directly read the full context ledger, aggregate memory, prior reports, or prior analysis/decision archives.
4. Preserve the Claude Code-era guardrails from committed authority, not from the ignored `.claude` mirror. These are mandatory: `memory/independent-report-no-user-reference.md`, `memory/precise-numbers-no-fuzzy.md`, `memory/report-chinese-only-narrative.md`, `memory/notion-publish-checklist.md`, and `memory/stability-contract.md`.
5. Keep this workflow isolated. Do not invoke or mix `quant-summary` or any sibling workflow.
6. Optimize only deterministic collection and mechanical execution.
7. Before the analysis lock, do not read or use Notion actual-position facts for Maker/main decisions. Positions may be reconciled only after the independent report hash is locked, and may not change score, win rate, direction, entry, stops, targets, or whether Maker places an order.
8. Before collection, run `session_runner.py begin-session --date <date> --slot <slot>` and retain its lease token. Pass that token to capture and every subsequent runner command. A second slot/date may not begin until delivery closes the lease; interruption requires explicit `abandon-session` or `recover-session` with a reason.
9. Capture into the immutable manifest path printed by `capture_all.js`/`capture_delta.js`. A full baseline run must use `capture_all.js`, which runs `cleanup.js` first; do not bypass it with manual sub-captures. Cleanup only removes expired dynamic inbox screenshots and BlockBeats cards older than `CLEANUP_KEEP_DAYS` days, never current-day evidence or immutable snapshots. BlockBeats must be collected with the page's `重要快讯` filter selected and must cover all available important flashes from the 12 hours before the capture time; require `blockbeats.json` to contain `"important_only": true`, `"capture_window_hours": 12`, `"window_covered": true`, at least three `candidate_rows`, exactly three `selected_rows`, and `rows` equal to the selected top3 by fundamental-impact priority. Farside BTC ETF Flow is a required source: require `farside_btc_etf.png` and `farside_btc_etf.json`, with title `Bitcoin ETF Flow (US$m)`, a parsed Total column, and numeric latest daily `total_usd_m`. Hard-stop instead of falling back to unfiltered news, a shorter BlockBeats window, stale ETF-flow data, or inferred ETF-flow numbers. After collection and before source validation, confirm the highest available model and MAX effort, then run `session_runner.py prepare` with `--capture-manifest <exact path> --lease-token <token> --max-reasoning-confirmed`; halt if this cannot be confirmed.
10. Use MAX reasoning for source validation, visual transcription, analysis, scoring, win rate, risk, scenarios, decisions, writing, and review.
11. Recompute the complete analysis from the full valid six-source evidence for every morning, midday, and evening report. Never reuse prior features, scores, win rate, risk, or judgment. The six required sources are BlockBeats, Coinglass, Exocharts, FedWatch, Farside BTC ETF Flow, and TradingView. Farside must be used as the spot-side liquidity confirmation signal: price down + ETF outflow confirms/strengthens bearish health, price up + ETF inflow confirms/strengthens bullish health, and disagreement weakens the move. A logic/methodology hash change invalidates analysis only and never authorizes redundant evidence capture.
    Golden reasoning alignment is the learned compact contract in `scoring/golden_report_reasoning_alignment.md`, not a runtime comparison against historical Word files. After `prepare`, the runner writes `runtime_state/<date>/golden_reasoning_<slot>.json`; do not reopen pre-2026-06-26 local Word/combined reports, and do not pad the MD after output to mimic length, price-reference count, or rubric count. Reasoning style, depth, and dimensions are hard aligned; old Word/Notion formatting only needs near-100% alignment while field semantics, trading numbers, Word QA, and publish verifiers remain hard gates.
12. Maker floating-defense first layer must use a 4H candle extreme: 4H high for shorts and 4H low for longs. Never use 1H/15m/hourly wording for the first layer.
13. After lint passes, run `session_runner.py lock-analysis ... --lease-token <token>` with the independent-analysis confirmations. Do not read prior-session directions, scores, win rate, Maker decisions, or Notion actual-position facts until this report-hash-bound lock exists.
14. Review prior-plan continuity after the lock; for evening, also complete the independent review. Then run `session_runner.py finalize-post-lock ... --lease-token <token>` with the applicable confirmations.
15. Commit only through `session_runner.py commit ... --lease-token <token>`; it must validate the analysis lock, post-lock completion, report completeness, source coverage, and state allowlist.
16. Render only with `render_from_combined.py <combined> --date <date> --slot <slot>`. It produces exactly `outputs/<date>_<slot>_render.docx`, reuses a matching hash-bound result, blocks lone `>`/bad titles, and hard-stops before a third attempt. From 2026-07-05 onward, `outputs/report_structure_gate.py` is a hard gate before render, before publish, and after DOCX render: human-facing titles must use `YYYY.M.D`, the combined draft must keep `## ① 正文` -> `## 不能做` -> `## ② Maker 计划` -> `## ③ 后附`, raw `---` is forbidden, legacy `五源` wording is forbidden, and the appendix must cover all six sources including Farside BTC ETF Flow.
17. Run `word_qa.py export`, inspect every generated page at MAX, then run `word_qa.py approve --confirm-visual-pass --reviewer <host>`. Do not create V2/V3/report/Chinese-named DOCX copies or temporary VBS/PS1 render scripts.
18. Publish through `publish_report.py`. Only after the render, Word-QA and publish manifests exist, append the exact final page id/time/PASS to `context_log.md`; then run `session_runner.py deliver --date <date> --slot <slot> --page-id <id> --lease-token <token>`. Boolean self-attestation is not delivery evidence.
19. Treat user phrases such as `收工`, `如无问题即收工`, `完成后收工`, or any final-completion response as a hard completion trigger. Do not say the report is complete until the scoped completion gate is closed:
    - For actual daily-report delivery: lint/freshness, render manifest, Word-QA manifest with `status=passed`, publish manifest, online verifier `[PASS]` with exit code 0, unique live Notion page, final `context_log.md` entry, `session_runner.py deliver` success, and temporary cleanup are all complete. Evening delivery also requires the independent review artifact/page.
    - For workflow maintenance/audit tasks that do not publish a report: update committed authority/tests in scope, run the relevant regression checks, stage only scoped files, commit only when explicitly requested, and report any unrelated dirty files instead of hiding them.
20. Record mechanical phase usage with `runtime/usage_logger.py` where available, including `render_docx`, `word_export`, `visual_qa`, `publish`, and `delivery`; use real token counts when the host exposes them and `null` when it does not. Never estimate token counts.
21. After delivery, remove temporary relay files matching `sessions/_*.txt`; never delete locked evidence snapshots, manifests, render QA, publish evidence, or same-day dynamic source files.
22. If MAX reasoning resources or required evidence are unavailable, halt instead of degrading quality.
23. Bind every report to its own immutable slot evidence snapshot (date + slot + actual capture time + source hashes). Morning, midday, and evening captures and reports are independent. A later slot must never overwrite, refresh, reinterpret, or satisfy freshness for an earlier slot. Publication, Word QA, ledger logging, and delivery must all use the same locked report hash and slot-bound evidence snapshot. See `memory/report-evidence-time-lock.md`.
