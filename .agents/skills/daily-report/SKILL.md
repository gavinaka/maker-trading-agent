# Trading-System Daily Report

1. Read `sessions/日报SOP.md` completely; it is the committed executable authority for Codex runs.
2. If `.claude/skills/daily-report/SKILL.md` exists on this machine, treat it only as a local Claude Code compatibility mirror. It may be consulted for drift detection, but it is not allowed to override `sessions/日报SOP.md` or any committed authority file because `.claude/` is git-ignored.
3. Run `runtime/context_pack.py --date <date> --slot <slot>` once and inspect its `authority_sha256`, `authority_manifest`, `authority_read_plan`, and `read_policy.prelock_safe_read_policy`. Always read the mandatory guardrails in `read_policy.mandatory_guardrails_always_read`; expand the remaining authority files by the current phase/source need instead of loading the full 50-file authority set blindly. If the authority digest changed unexpectedly or the phase need is ambiguous, read the affected authority files before proceeding. Before the analysis lock, never directly read the full context ledger, aggregate memory, prior reports, old outputs, old runtime state, reviews, quarantine files, or prior analysis/decision archives. Do not run naked repository-wide search for pre-lock facts; use explicit paths from the context pack/read plan or the safe rg excludes from `runtime/prelock_read_policy.py`.
4. Preserve the Claude Code-era guardrails from committed authority, not from the ignored `.claude` mirror. These are mandatory: `memory/independent-report-no-user-reference.md`, `memory/precise-numbers-no-fuzzy.md`, `memory/report-chinese-only-narrative.md`, `memory/notion-publish-checklist.md`, and `memory/stability-contract.md`.
5. Keep this workflow isolated. Do not invoke or mix any sibling or cross-workflow process.
6. Optimize only deterministic collection and mechanical execution.
7. Before the analysis lock, do not read or use Notion actual-position facts for Maker/main decisions. Positions may be reconciled only after the independent report hash is locked, and may not change score, win rate, direction, entry, stops, targets, or whether Maker places an order.
8. Before collection, run `session_runner.py begin-session --date <date> --slot <slot>` and retain its lease token. Pass that token to capture and every subsequent runner command. A second slot/date may not begin until delivery closes the lease; interruption requires explicit `abandon-session` or `recover-session` with a reason. If an immutable same-date/same-slot capture manifest already completed successfully before an audited hard stop closed the original lease, do not edit the manifest and do not hand-copy evidence. Resume only by running `session_runner.py recover-session --date <date> --slot <slot> --from-lease-id <capturing_lease_id> --reason <explicit reason>` and then `prepare` with the new lease token and the exact old manifest path; the runner must record `recovered_from_workflow_lease` and `capture_lease_recovery`. If the archived lease cannot be validated, rerun capture instead of bypassing the lease gate.
9. Capture into the immutable manifest path printed by `capture_all.js`/`capture_delta.js`. A full baseline run must use `capture_all.js`, which runs `cleanup.js` first; do not bypass it with manual sub-captures. For midday/evening, `capture_delta.js` is still required to refresh all six sources; delta means conservative sequencing, source fingerprint comparison, and one bounded full fallback, not permission to skip FedWatch or reuse morning/prior evidence. Capture cleanup only removes expired dynamic inbox screenshots and BlockBeats cards older than `CLEANUP_KEEP_DAYS` days, never current-day evidence or immutable snapshots. Post-delivery retention cleanup is automatic: successful `session_runner.py deliver` executes `runtime/report_retention.py`, writes `runtime_state/<date>/retention_cleanup_<slot>.json`, keeps canonical local Word drafts, Notion pages, delivery/lease/automation minimal state, and removes older reproducible local non-Word artifacts according to `REPORT_RETENTION_KEEP_DAYS` days. Use `--skip-retention-cleanup` only for explicit troubleshooting. BlockBeats must be collected with the page's `重要快讯` filter selected and must cover all available important flashes from the 12 hours before the capture time; require `blockbeats.json` to contain `"important_only": true`, `"capture_window_hours": 12`, `"window_covered": true`, at least three `candidate_rows`, exactly three `selected_rows`, and `rows` equal to the selected top3 by fundamental-impact priority. Farside BTC ETF Flow is a required source: require `farside_btc_etf.png` and `farside_btc_etf.json`, with title `Bitcoin ETF Flow (US$m)`, a parsed Total column, and numeric latest daily `total_usd_m`. Hard-stop instead of falling back to unfiltered news, a shorter BlockBeats window, stale ETF-flow data, or inferred ETF-flow numbers. After collection and before source validation, confirm the highest available model and MAX effort, then run `session_runner.py prepare` with `--capture-manifest <exact path> --lease-token <token> --max-reasoning-confirmed`; halt if this cannot be confirmed.
   `prepare` also activates `runtime/prelock_guard.py`: prior-session judgment artifacts (`sessions/context_log.md`, prior `analysis_*.json`/`decision_*.json`, prior combined/payload/render outputs) are quarantined until `lock-analysis` succeeds, and the guard manifest embeds the safe pre-lock read policy. The repository `.rgignore` hides known prior-judgment surfaces from default `rg`, but this is a guardrail, not permission to search broadly. Do not bypass this guard, manually restore/read quarantine files, or search `sessions/archive/**`, old `outputs/**`, old `runtime_state/**`, `reviews/**`, or `memory/MEMORY.md` before the report hash is locked. `lock-analysis` restores guarded files for post-lock continuity review; `abandon-session`/`recover-session` restore them on interruption.
10. Use MAX reasoning for source validation, visual transcription, analysis, scoring, win rate, risk, scenarios, decisions, writing, and review.
11. Recompute the complete analysis from the report slot's freshly collected full valid six-source evidence for every morning, midday, and evening report. Never reuse prior evidence snapshots, features, scores, win rate, risk, or judgment. The six required sources are BlockBeats, Coinglass, Exocharts, FedWatch, Farside BTC ETF Flow, and TradingView. Farside must be used as the spot-side liquidity confirmation signal: price down + ETF outflow confirms/strengthens bearish health, price up + ETF inflow confirms/strengthens bullish health, and disagreement weakens the move. A logic/methodology hash change invalidates analysis only and never authorizes redundant evidence capture.
    Golden reasoning alignment is the learned compact contract in `scoring/golden_report_reasoning_alignment.md`, not a runtime comparison against historical Word files. After `prepare`, the runner writes `runtime_state/<date>/golden_reasoning_<slot>.json`; do not reopen pre-2026-06-26 local Word/combined reports, and do not pad the MD after output to mimic length, price-reference count, or rubric count. Reasoning style, depth, and dimensions are hard aligned; old Word/Notion formatting only needs near-100% alignment while field semantics, trading numbers, Word QA, and publish verifiers remain hard gates.
12. Before writing the formal `outputs/<date>_<slot>_combined.md`, create the internal pre-output work file `runtime_state/<date>/reasoning_work_<slot>.md` from the completed MAX analysis. It must cover six-source accuracy, pivot/CVD/SMA20/VRVP calibration, score synthesis, win-rate rubric, refutation/invalidation, and risk math. Then run `session_runner.py certify-reasoning --date <date> --slot <slot> --work-file runtime_state/<date>/reasoning_work_<slot>.md --capture-manifest <exact path> --lease-token <token> --confirm-six-source-accuracy --confirm-critical-data-calibrated --confirm-score-winrate-risk-refutation --confirm-no-formal-md-written --confirm-no-posthoc-reasoning --confirm-max-reasoning`. From 2026-07-06 midday onward, `combined.md` is forbidden before this readiness manifest. Posthoc rationale or rubric backfill is a hard violation.
13. Maker floating-defense first layer must use the 4H candle extreme that forms and is confirmed after the Maker order is filled: use the post-entry confirmed 4H high extreme for shorts and the post-entry confirmed 4H low extreme for longs. The report may precompute the first-layer trigger price, but must not prefill the future extreme stop price from historical/current 4H highs/lows, 1D highs/lows, or any already-known price. Never use 1H/15m/hourly wording for the first layer.
14. After the formal `combined.md` is written from the certified reasoning work file and lint passes, run `session_runner.py lock-analysis ... --lease-token <token>` with the independent-analysis confirmations. Do not read prior-session directions, scores, win rate, Maker decisions, or Notion actual-position facts until this report-hash-bound lock exists.
15. Review prior-plan continuity after the lock; for evening, also complete the independent review. Then run `session_runner.py finalize-post-lock ... --lease-token <token>` with the applicable confirmations.
16. Commit only through `session_runner.py commit ... --lease-token <token>`; it must validate the analysis lock, pre-MD reasoning readiness, post-lock completion, report completeness, source coverage, and state allowlist.
17. Render only with `render_from_combined.py <combined> --date <date> --slot <slot>`. It produces exactly `outputs/<date>_<slot>_render.docx`, reuses a matching hash-bound result, blocks lone `>`/bad titles, and hard-stops before a third attempt. From 2026-07-06 midday onward render also requires a hash-bound analysis lock that contains pre-MD reasoning readiness. From 2026-07-05 onward, `outputs/report_structure_gate.py` is a hard gate before render, before publish, and after DOCX render: human-facing titles must use `YYYY.M.D`, the combined draft must keep `## ① 正文` -> `## 不能做` -> `## ② Maker 计划` -> `## ③ 后附`, raw `---` is forbidden, legacy `五源` wording is forbidden, and the appendix must cover all six sources including Farside BTC ETF Flow.
18. Run `word_qa.py export`, inspect every generated page at MAX, then run `word_qa.py approve --confirm-visual-pass --reviewer <host>`. Do not create V2/V3/report/Chinese-named DOCX copies or temporary VBS/PS1 render scripts.
19. Build daily Notion payloads only with `py outputs/daily_payload_builder.py outputs/<date>_<slot>_combined.md`; the combined Markdown is the only daily text source of truth, and hand-written `children` JSON or date-specific `_prepare_*` / `_notion_push_*` scripts are forbidden for new daily reports. Then publish through `publish_report.py`, which must verify `payload_source.kind=combined_md_to_notion_payload` and, from 2026-07-06 midday onward, the hash-bound analysis lock with pre-MD reasoning readiness before any Notion write. Parameterized daily payloads must be normalized to the `daily-gold-run-colors-v1` Notion run-level color template before any Notion write: labels stay default, fundamental parenthetical reasoning stays yellow, only the standalone price-realization phrase is green, technical daily/hourly paragraphs color their key signal clause such as regained/lost SMA or trendline pressure, trend confirmation colors the whole trend conclusion by its primary direction, support/pressure/TP/SL/notes use green/red/purple, and whole-block coarse coloring is forbidden. Only after the render, Word-QA and publish manifests exist, append the exact final page id/time/PASS to `context_log.md`; then run `session_runner.py deliver --date <date> --slot <slot> --page-id <id> --lease-token <token>`. Boolean self-attestation is not delivery evidence.
    Evening independent review is a separate hard contract, not a free-form payload. It must not generate extra HTML, screenshots, Word, or PDF artifacts, and it must not require or validate daily `source_specs`, daily freshness/lint, or daily source-binding gates. Build review payloads only with `py outputs/review_payload_builder.py runtime_state/<date>/evening_independent_review.json` from an `evening-independent-review-v2` manifest. Review publishing must pass `outputs/review_contract.py`: the first table is fixed to `维度 / 前一晚报 / 当天早报 / 当天午报 / 综合` with rows `方向判断 / 入场结构 / 风险框架 / 数据精度 / 内在一致性 / 综合`; the price ladder and findings must cover all three prior segments; visible Notion text must not contain runner/lock/commit/payload/verifier/Word-QA/context_log terms; `payload_source` must bind the manifest, report hash, and children signature. The frozen `notion_verify_against_yesterday.py <page_id> review` gate must pass after publish.
    Review payloads must also pass `review-font-rendering-v1`: score cells, price-ladder segment/opinion cells, findings, boundary, and final conclusion must contain Notion `rich_text.annotations.color` and required bold annotations. Unstyled native blocks are invalid.
20. Treat user phrases such as `收工`, `如无问题即收工`, `完成后收工`, or any final-completion response as a hard completion trigger. Do not say the report is complete until the scoped completion gate is closed:
    - For actual daily-report delivery: lint/freshness, render manifest, Word-QA manifest with `status=passed`, publish manifest, online verifier `[PASS]` with exit code 0, unique live Notion page, final `context_log.md` entry, `session_runner.py deliver` success, `retention_cleanup_<slot>.json`, and temporary cleanup are all complete. Evening delivery also requires the independent review manifest/payload and Notion page, with no HTML/screenshot/Word/PDF review artifact.
    - For workflow maintenance/audit tasks that do not publish a report: update committed authority/tests in scope, run the relevant regression checks, stage only scoped files, commit only when explicitly requested, and report any unrelated dirty files instead of hiding them.
21. Record mechanical phase usage with `runtime/usage_logger.py` where available, including `render_docx`, `word_export`, `visual_qa`, `publish`, and `delivery`; use real token counts when the host exposes them and `null` when it does not. Never estimate token counts.
22. After delivery, remove temporary relay files matching `sessions/_*.txt`. Do not delete same-day or still-retained dynamic source files, locked evidence, manifests, render QA, or publish evidence. Successful `session_runner.py deliver` automatically executes retention cleanup for artifacts older than the retention window; keep canonical local Word drafts, Notion pages, and minimal delivery/lease/automation state.
23. If MAX reasoning resources or required evidence are unavailable, halt instead of degrading quality.
24. Bind every report to its own immutable slot evidence snapshot (date + slot + actual capture time + source hashes). Morning, midday, and evening captures and reports are independent. A later slot must never overwrite, refresh, reinterpret, or satisfy freshness for an earlier slot. Publication, Word QA, ledger logging, and delivery must all use the same locked report hash and slot-bound evidence snapshot. See `memory/report-evidence-time-lock.md`.
