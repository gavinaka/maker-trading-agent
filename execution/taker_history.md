# Taker 账户历史档案（图谱一节 + 六节）

> Taker 账户已于 **2026-03-08 正式合并到主账户**（暂停）。
> 本文件保留历史定义，仅用于：
> 1. 理解早期文档中提到的 Taker 概念
> 2. 历史数据复盘
> 3. 未来若需重启 Taker 账户的参考

**当前系统中不再有独立的 Taker 账户。**

---

## 历史定义（合并前）

### 角色（合并前）
- **机会博弈**（右侧 / 盘口）
- 每日 ≤ 1 次
- 每周 ≤ 3 次
- 历史交易所：OKX

### 策略类型 B：Taker（至少两次流动性）

#### 核心要求
* 至少两次流动性猎杀确认
* 仓位相对较小（$350-$750）
* 不做隔夜
* 短线为主
* 需要实时盯盘

#### 触发条件
* 满足全部启用条件才可执行
* 含 Maker 挂单区 + 止损点位确认

## 合并历史

### 合并时点
**2026-03-08**

### 合并原因
* Taker 与主账户均使用更细粒度操作但分属不同账户，运营开销大
* Taker 历史上有 V005 违规（**2025.10.21 冒然 Taker 阶段，系统受损**）
* 单一账户体系更利于"洁净样本打造"目标
* 简化执行节奏，避免账户切换造成的注意力分散

### 合并后状态
* 原 Taker 账户的"机会博弈"功能 → 并入主账户的中线决策（按需触发）
* 原 Taker 仓位规模（$350-$750）→ 不再使用
* 原"动态 Taker 机会槽"数据库 → **保留记录**但不再产生新数据

## 动态 Taker 机会槽规则（图谱二十节，仅历史档案）

### 使用上限
| 项 | 上限 |
|---|---:|
| 每日 | ≤ 1 次 |
| 每周 | ≤ 3 次 |

### 触发条件
满足**全部**启用条件才可执行：
* Maker 挂单区已确认
* 止损点位已确认
* 评分系统通过（≥ 70）
* 主账户方向允许
* 状态门禁通过

### 记录字段（7 字段）
```json
{
  "time": "<ISO 时间戳>",
  "symbol": "BTCUSDT | ETHUSDT",
  "position_size_usd": <number, 历史区间 $350-$750>,
  "maker_used_status": "已使用 | 未使用",
  "opportunity_trigger_record": "<触发详情：哪些条件满足>",
  "execution_result": "已执行 | 未执行 | 已取消",
  "pnl_ratio": "<盈亏比 如 1:2.8>"
}
```

### 历史数据位置
* Notion 数据库：「动态 Taker 机会槽」（保留只读）

## entry_mode 字段歧义说明

注意：`check_records[].entry_mode` 字段值 = "Maker" 或 "Taker"，**指挂单方式**（限价/市价），**不是账户名**。

| entry_mode 值 | 含义 |
|---|---|
| Maker | 限价挂单 |
| Taker | 市价吃单 |

→ 即使在主账户或 Maker 账户下，单笔交易也可能使用 Taker 挂单方式。

## 未来重启可能性

如果未来需重启独立 Taker 账户：
1. 必须先完成洁净样本 50 笔目标（评估系统成熟度）
2. 必须重读 V005 违规案例（避免重蹈覆辙）
3. 必须用户主动决策，agent 不可自动触发
4. 重启后新增账户的整套规则文档 + state + agent
