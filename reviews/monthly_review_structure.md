# 月报结构定义（图谱十九节）

> 本文件定义月报的**结构规范**。
> 模板渲染见 `templates/monthly_review.md`。
> Schema 见 `schemas/review_schema.json` → `monthly_review`。

---

## 核心信息

* **时点**：每月最后一天 23:00（自然月）
* **覆盖**：本月 1 日至本月末（GMT+8）
* **文件命名**：`reviews/<YYYY-MM>_monthly.md`（如 `reviews/2026-05_monthly.md`）
* **责任 Agent**：`review_agent`

---

## 当前标准结构

### 一、资金仓位复盘

| 字段 | 计算 |
|---|---|
| 本金 | 固定 $1200 |
| 现有资金（OKX） | 用户输入（月末余额） |
| 现有资金（Binance） | 用户输入（月末余额） |
| 合计 | OKX + Binance |
| 净亏损总额 | $1200 - 合计 |
| 同比上月 | 对比上月 monthly.md |
| 小结 | 用户输入 |

### 二、持仓情况

#### 主账户
- 持仓 / 浮盈浮亏 / 防守层级 / 月内迭代次数

#### Maker
- 月末持仓状态 + 资金

### 三、策略复盘（分账户）

#### Maker 账户
- 策略笔数 / 击中率 / 总盈亏 / PCT / 平均盈亏比 / 洁净样本贡献

#### 主账户中线计划
- 持仓天数 / 防守层级演变 / 浮盈浮亏 / 累计 PCT / 是否减仓加仓

### 四、ALL Review

- 整月核心问题复盘（≥ 3 条）
- 违规与洁净样本统计
- 下月目标（具体可执行，≥ 3 条）

## 与周报 / 日复盘的关系

```
日复盘 × 7 → 周报
周报 × 4-5 → 月报

月报数据聚合：
  ├─ Maker 策略笔数 = 当月所有 check_records.account=="maker" 计数
  ├─ 击中率 = profit==true 比例
  ├─ 平均盈亏比 = avg(rr_actual)
  ├─ 洁净样本贡献 = 当月 clean_sample_eligible 计数
  ├─ 持仓天数 = 持仓开始日至月末
  ├─ 防守层级演变 = month_start.defense_layer → month_end.defense_layer
  ├─ 累计 PCT = (current_price - average_entry) / average_entry × leverage × direction_sign
  └─ 违规统计 = 当月 governance/violations/*.json 聚合
```

## 月报触发要求

* 月末最后一天 23:00 自动触发（review_agent 调度）
* 月末未触发 → review_agent 在次月第 1 天补触发并标 "delayed"
* 错过 ≥ 2 天 → alert，强制人工介入

---

## ALL Review 核心问题复盘要求

### 数据线索（review_agent 提供给用户）
* 本月 4-5 个周报的"核心洞察"列表
* 本月违规清单（按类型分组）
* 本月评分分布直方图（70+ 的次数 / 50-69 / 0-49）
* 本月主账户中线计划迭代史
* 本月情绪事件高峰

### 用户产出
* 至少 3 条整月问题复盘（基于上述线索）
* 至少 3 条下月目标（具体可执行）

---

## 下月目标要求

* **禁止空话**："提高水平"/"减少违规" ✗
* **必须含数字或动作**：
  * ✓ "完成 5 笔洁净样本"
  * ✓ "周报关键洞察 ≥ 2 条"
  * ✓ "本月违规重度 = 0"
  * ✓ "中线持仓减仓达 TP1 时严格执行"

---

## 禁止行为

* 禁止 AI 生成核心问题复盘或下月目标
* 禁止"现有资金"使用估算
* 禁止跳过违规统计
* 禁止历史财务对照少于 3 个月
* 禁止覆盖历史月报
