# 系统演化史（图谱十三节 + 十五节 + 十九节）

> 记录交易系统从 2025.6 至今的关键演化节点。

> 1. 理解当前规则的"为什么"
> 2. 避免回退已被淘汰的做法
> 3. 给未来迭代提供参照

## 三、日报格式演化（图谱十五节）

### 阶段一：2025.12（合并期）
- 主账户计划与 Maker 计划写在**同一篇**日报
- BlockBeats 新闻以**完整文字形式**记录（非截图）
- 交易所：**Binance**
- 趋势确认格式：**两级评估**（如"长线空头趋势 短线震荡"）
- 策略段含"主账户中线计划" + "中短线计划新增"
- 盘口描述格式：CVD[方向] 价格[方向] 持仓[状态] 资金费率[描述]

### 阶段二：2026.1（分离期）
- 主账户日报与 Maker 计划**开始分开**记录
- BlockBeats 新闻**切换为截图**
- 交易所：**OKX + Binance 混用**
- 趋势确认向**单一词汇**过渡

### 阶段三：2026.3 至今（标准化期）
- **完全分离**：主账户日报 + Maker 计划独立
- BlockBeats 新闻**完全截图化**（硬性要求）
- 交易所：**纯 OKX（Maker）+ Binance（中线）**
- 趋势确认：标准三词（多头/空头/震荡）+ 修饰词
- 单笔 3% 止损硬规则写入风控清单

→ **2026.5.29 起加入**：Trading-System 工程化（agents + state + manifest + collectors + schemas + templates）

## 四、周报格式演化（图谱十九节）

### 早期（2025.6-9，AI 辅助期）
- ChatGPT 生成分析报告
- 概览数据 + 执行力评分表 + 盈亏结构 + 情绪行为分析

- 五维度评分表（★★★★☆格式）

- 简化为"四个核心问题复盘"
- 完全个人书写
- 引入"第二/三关"心理关卡命名

- 资金复盘 + 策略复盘 + 总结三段式
- 关键词体系命名
- 与 check_records 联动

## 十一、Notion 数据库与本系统的关系

* **Notion**：交易计划 + 交易 Check + 周报/月报 + 惩罚机制 等多个数据库（用户主操作界面）
* **Trading-System（本仓库）**：Agent + 模板 + Schema + State 等系统化引擎（程序操作）
* 两者同步：用户在 Notion 输入 → 本系统读 state → agents 处理 → 输出供 Notion 引用

→ 本系统 review_agent 写的 `check_records.json` 用户需在每周日补回 Notion 数据库。
